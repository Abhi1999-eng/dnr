# DNR Deep SEO Audit — 2026-09-29

Crawled all 33 live URLs in `sitemap.xml` and reviewed the metadata helpers, JSON-LD
producers, sitemap, robots, CMS settings model, and admin UI.

## Baseline: already correct, left alone

Every one of the 33 URLs returned 200, had exactly one `<h1>`, a correct self-referencing
canonical, an Open Graph image, and zero images missing `alt` text. `robots.txt`, `sitemap.xml`,
and `/llms.txt` were all served correctly, and Organization / WebSite / WebPage / BreadcrumbList /
FAQPage / Article schema was present throughout. The August audit covered this ground well; this
pass did not redo it.

## Fixed

### Local SEO and Google Business Profile

| Problem | Fix |
| ------- | --- |
| No `LocalBusiness` schema anywhere — only `Organization`, which Google does not use for Business Profile matching | Added `buildLocalBusinessJsonLd`, emitted site-wide from the root layout alongside the existing consolidated nodes |
| Whole address emitted as one `streetAddress` blob, so Google saw no city, state, or PIN code | Added `parsePostalAddress` to split it into `streetAddress` / `addressLocality` / `addressRegion` / `postalCode`, with explicit CMS overrides |
| `settings.socialLinks` was read by `lib/seo.ts` but **never declared in the Mongoose schema**, so `sameAs` could never populate | Declared the field; added `googleBusinessProfileUrl`, which leads `sameAs` |
| No geo, opening hours, map link, or price range | Added all four, emitted only when configured |
| `areaServed` said "India" while the CMS listed 10 specific states | `areaServed` now enumerates the configured states |
| Organization description came from a 42-character tagline | Falls back to the longest genuine copy available, capped at 300 characters |

Every local field is omitted when unset rather than guessed: a coordinate or an opening hour that
disagrees with the verified Business Profile is worse than a missing one. Partial or `0,0`
coordinates and incomplete opening-hour rows are dropped rather than emitted.

### Titles

Five titles were long enough to be truncated in search results, up to 109 characters. They were
keyword-stuffed with two phrases plus the brand; the secondary phrase moved into the description,
where it still counts.

| Page | Before | After |
| ---- | -----: | ----: |
| `/products/hot-chamber-zinc-die-casting-machine` | 109 | 58 |
| `/products/vertical-squeeze-casting-machines` | 108 | 55 |
| `/products/cold-chamber-die-casting-machine` | 100 | 61 |
| `/products/aluminium-gdc-machine` | 96 | 59 |
| `/products` | 93 | 57 |
| `/services` | 84 | 62 |
| `/about` | 65 | 54 |

`/products/core-shooter` (34) and `/products/brass-gdc-machine` (39) had no SEO entry at all and
fell back to the bare product name; both now have keyword-led titles and full descriptions.

### Descriptions

`trimDescription` stopped at the first sentence boundary past 55% of the limit, so a description
that opened with one short sentence lost up to 70 characters of snippet — `/products/aluminium-gdc-machine`
was rendering 93 characters out of an available 160. The threshold is now 80%.

Truncation could also strand a connecting word, producing snippets ending "...engineering services for."
Trailing connectives are now removed.

Two listing pages passed short CMS display fields straight through as meta descriptions:
`/services` used a 66-character section kicker, and `/products` used *the first product's* summary,
so the catalogue description changed whenever product ordering changed. Both now go through
`pickMetaDescription`, which rejects candidates under 110 characters.

### Sitemap

Static pages reported `lastModified: new Date()` — the time of the request — so `lastmod` always
read "now", which Google learns to ignore. It is now derived from real content timestamps. Product,
service, and blog entries also carry their images for image search.

### Guard against regression

`createPageMetadata` now warns in development when a title exceeds 65 characters or a description
falls under 110. This caught an 87-character homepage title during verification, which is fixed.

## Not fixed — needs the owner

- **The Google Business Profile listing itself.** Claiming, verifying, categories, hours, photos,
  and reviews all need an owner signed in to the listing. See [`google-business-profile.md`](google-business-profile.md).
- **Three values only the listing can supply** — the Business Profile URL, latitude/longitude, and
  the map link. Admin → Settings → Google Business Profile & local SEO now has fields for these;
  the schema picks them up as soon as they are saved.
- **Two phone numbers.** The site publishes +91 9911399919 and +91 9711196735. Pick one as the
  listing's primary and keep it identical everywhere.
- **Titles held in the database.** `/services/tie-bar-strain-gauge-services-for-pressure-die-casting-machines`
  renders an 85-character title, and the two blog posts render 83 and 86. These come from CMS
  content, not code, so they need editing in the admin UI.
- **Homepage weight.** The homepage ships roughly 576 KB of HTML with 56 images, which is the most
  likely drag on Core Web Vitals. Worth a separate pass.
